## 1. Workflow

- [ ] **Confirm** — [ ] **Change** — One profile exists per person, identified by a unique control number from the external approved system.
- [ ] **Confirm** — [ ] **Change** — Staff may create a draft profile before that control number is available. The control number is required before a request can be submitted for processing.
- [ ] **Confirm** — [ ] **Change** — A control number already assigned to another profile is blocked. Staff are directed to the existing profile.
- [ ] **Confirm** — [ ] **Change** — Staff and administrators may correct a control number. The correction requires a reason and is kept in history.
- [ ] **Confirm** — [ ] **Change** — Only administrators may merge two profiles for the same person. The merge keeps all requests and history. The administrator resolves conflicting values and records a reason.
- [ ] **Confirm** — [ ] **Change** — An applicant may have only one open request at a time.
- [ ] **Confirm** — [ ] **Change** — A new request starts only after the previous request is closed and its access has ended.
- [ ] **Confirm** — [ ] **Change** — A vendor change requires an externally confirmed end of the old access, then a fresh request for the new vendor.
- [ ] **Confirm** — [ ] **Change** — A returning applicant reuses the existing profile and receives a new request and checklist. Previous requests stay as history. Previous access is not restored.
- [ ] **Confirm** — [ ] **Change** — A request moves from Draft to Pending only when these are present: applicant name, vendor, requestor, requested access type, email, phone, the date the information was provided, and the external control number. Staff then select **Submit for Processing**.
- [ ] **Confirm** — [ ] **Change** — Processing follows this order: III check, fingerprints, security awareness training, signed security addendum, NCIC certification, external decision.
- [ ] **Confirm** — [ ] **Change** — Staff may record a later step before an earlier step is finished. The displayed stage stays on the earliest incomplete step.
- [ ] **Confirm** — [ ] **Change** — Staff may override the calculated stage. The override requires a recorded reason.
- [ ] **Confirm** — [ ] **Change** — Full Clearance and One Time Visit use the same checklist.
- [ ] **Confirm** — [ ] **Change** — Every checklist item is mandatory. NCIC certification is the exception: staff or administrators may mark it Not Applicable with a recorded reason.
- [ ] **Confirm** — [ ] **Change** — External decisions are recorded as Full Clearance, One Time Visit, or No Access Given. Each decision includes the decision date and the external decision-maker’s name.
- [ ] **Confirm** — [ ] **Change** — One access-type field is updated to match the latest external decision. Earlier values remain in change history.
- [ ] **Confirm** — [ ] **Change** — If Full Clearance or One Time Visit is received before the checklist is complete, the decision is saved. Limited View shows No Access Given until the checklist is complete.
- [ ] **Confirm** — [ ] **Change** — One Time Visit access uses an Albuquerque local window, including daylight-saving time. Staff may enter a full-day date range or a precise start and end. Access is active only inside that window, and only after the checklist is complete.
- [ ] **Confirm** — [ ] **Change** — Staff and administrators may reschedule a visit with a recorded reason. The same checklist is reused. Expired requirements are flagged.
- [ ] **Confirm** — [ ] **Change** — After a visit window ends, routine reminders stop. History and unresolved issues remain visible.
- [ ] **Confirm** — [ ] **Change** — If a requirement expires during an active visit, the tracker shows Review Required and alerts staff. The visit window stays as approved until an external decision changes it.
- [ ] **Confirm** — [ ] **Change** — Full Clearance may have an optional access end date for a contract or assignment with a known end. When that date passes, the tracker shows Review Required until staff record the external end-of-access decision.
- [ ] **Confirm** — [ ] **Change** — A revocation includes an effective date and time in Albuquerque local time. If staff enter it after that time has passed, the tracker shows No Access Given immediately and keeps both the effective time and the entry time.
- [ ] **Confirm** — [ ] **Change** — Before a future revocation takes effect, Limited View shows the current access status and “Access ends [date/time].”
- [ ] **Confirm** — [ ] **Change** — Staff and administrators may correct or cancel a scheduled revocation when a revised external decision is received. The change requires a reason and is kept in history.

## 2. Renewals, queue, and email

- [ ] **Confirm** — [ ] **Change** — Five-year query deadlines stay anchored to the original III completion date, including when a repeat query is completed late.
- [ ] **Confirm** — [ ] **Change** — Completing a late query clears the overdue flag. The next deadline stays on the original schedule. Example: a query due in 2025 and completed in 2026 has its next deadline in 2030.
- [ ] **Confirm** — [ ] **Change** — Every query completion is kept in history.
- [ ] **Confirm** — [ ] **Change** — Administrators may correct a query date. The correction requires a reason, and the original value stays in history.
- [ ] **Confirm** — [ ] **Change** — A query-date correction recalculates overdue flags and retention-review dates. Correcting the original III completion date also recalculates the five-year schedule. Each recalculation keeps the previous dates, the revised dates, and the correction that caused it.
- [ ] **Confirm** — [ ] **Change** — Overdue security awareness training, an overdue five-year query, and overdue NCIC certification where it is required set the applicant to Review Required.
- [ ] **Confirm** — [ ] **Change** — A missing required date shows Information Missing and creates a follow-up. Access status stays unchanged.
- [ ] **Confirm** — [ ] **Change** — Review Required clears when every triggering issue is resolved. The access status that otherwise applies is restored. A denial or ended access remains in effect.
- [ ] **Confirm** — [ ] **Change** — Advance warnings appear 30, 14, and 7 days before a requirement is due.
- [ ] **Confirm** — [ ] **Change** — The Staff/Admin follow-up queue shows overdue items first, then missing information, then upcoming deadlines.
- [ ] **Confirm** — [ ] **Change** — Staff track follow-up in notes. An issue stays open until the underlying requirement is resolved.
- [ ] **Confirm** — [ ] **Change** — After a visit window ends, routine reminders stop. History and unresolved issues remain visible.
- [ ] **Confirm** — [ ] **Change** — The shared queue and internal daily email cover active applicants with overdue or missing requirements, and archived applicants with unresolved issues.
- [ ] **Confirm** — [ ] **Change** — Email and other notifications are a later phase. The first release uses the shared work queue.
- [ ] **Confirm** — [ ] **Change** — When email is added, it goes only to internal staff and administrators selected by an administrator. Applicants are not recipients.
- [ ] **Confirm** — [ ] **Change** — When email is added, the summary is sent at 8:00 a.m. Albuquerque time on weekdays, including a “No outstanding issues” message when the queue is clear. It lists applicant names, issue types, and due dates, and includes the 30-, 14-, and 7-day warnings.
- [ ] **Confirm** — [ ] **Change** — When email is added, a failed send is recorded on an administrators-only status page. The tracker does not retry it automatically and does not send a separate failure alert.

## 4. Retention

These statements are the retention rules from the later stakeholder answers. City records or legal confirmation is still a separate approval. The first release calculates review dates and does not delete records.

- [ ] **Confirm** — [ ] **Change** — Active records are kept until the person separates from the department.
- [ ] **Confirm** — [ ] **Change** — After deactivation, the proposed retention period is three years from the most recent III query date.
- [ ] **Confirm** — [ ] **Change** — Deactivation does not restart that three-year clock.
- [ ] **Confirm** — [ ] **Change** — If the three-year period has already elapsed when the applicant is deactivated, the record is flagged immediately for administrator retention review.
- [ ] **Confirm** — [ ] **Change** — A deactivated record with no III query date is kept and flagged as missing that date. No deletion deadline is calculated.
- [ ] **Confirm** — [ ] **Change** — Audit history has its own proposed retention of seven years after a request is deleted. That proposal stays pending City records or legal approval.
- [ ] **Confirm** — [ ] **Change** — Each request has its own retention clock. Updating an applicant’s contact details does not restart the clock on historical requests.
- [ ] **Confirm** — [ ] **Change** — Jessica Solis coordinates confirmation of these retention rules and the hold process with City records or legal.
- [ ] **Confirm** — [ ] **Change** — The first release calculates retention-review dates and flags eligible records for administrators. Archiving, deletion, and legal or records holds wait for a later release.
